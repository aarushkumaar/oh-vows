🚀 Deployment Options

Option 1: Vercel (Recommended)

Zero-configuration, automatic deployments from git, built-in analytics.

1 Install Vercel CLI
npm install -g vercel
2 Deploy
vercel --prod
✓ Your invitation is now live at a Vercel URL

To set up git-based deployments:

  1. Push your project to GitHub
  2. Go to vercel.com/import
  3. Select your repository
  4. Click Deploy
  5. Every push to main automatically deploys

Option 2: Netlify

Simple, free static hosting with excellent performance.

1 Build locally
npm run build
2 Deploy via Netlify CLI
npm install -g netlify-cli netlify deploy --prod --dir=dist

Option 3: Static Hosting (AWS S3, Google Cloud Storage, etc.)

1 Build
npm run build
2 Upload dist/ folder to your host

🔗 Setting Up Custom Domain

After deploying, add your custom domain (e.g., gul.example.com):

On Vercel:

  1. Go to Project Settings → Domains
  2. Add your domain
  3. Update DNS records as shown
  4. SSL certificate auto-generated

On Netlify:

  1. Go to Site Settings → Domain Management
  2. Add custom domain
  3. Update DNS or use name server delegation

🛠️ Environment Configuration

For backend integration (optional), create a .env.production file:

VITE_API_URL=https://api.example.com VITE_RSVP_ENDPOINT=https://api.example.com/rsvp VITE_CONTACT_EMAIL=wedding@example.com

Reference in code:

const apiUrl = import.meta.env.VITE_API_URL

📝 RSVP Backend Setup (Optional)

To actually collect RSVPs, set up a backend:

With Supabase (Recommended)

  1. Create Supabase account
  2. Create table: rsvps with columns:
    • id (UUID)
    • name (text)
    • guests (int)
    • attendance (text)
    • message (text)
    • created_at (timestamp)
  3. Enable row-level security (RLS)
  4. Update src/components/RSVP.tsx to call your backend

Example Backend Integration:

const handleRSVP = async (data: RSVPData) => { const response = await fetch( import.meta.env.VITE_RSVP_ENDPOINT, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(data) } ) if (response.ok) { setSubmitted(true) } }

⚡ Performance Optimization

Before Going Live: Run these checks
1. Image Optimization
  • Use WebP/AVIF for photography
  • Keep PNG only for transparency
  • Compress all images (TinyPNG, Squoosh)
2. Bundle Size
npm run build # Check dist/ folder size # Should be < 500KB for production
3. Lighthouse Audit
  • Run Lighthouse in DevTools (mobile & desktop)
  • Aim for 90+ on Performance, Accessibility, Best Practices

📞 Support & Troubleshooting

Images not loading?

Check that files are in public/assets/ and paths are correct

RSVP not working?

Check browser console for errors, verify backend URL in env variables

Animations laggy on mobile?

Reduce animation complexity, enable GPU acceleration with will-change

Site slow?

Run Lighthouse, compress images, enable CDN caching
